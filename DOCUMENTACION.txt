========================================
1. DESCRIPCION DEL PROYECTO
========================================

Este es un sistema web completo para la gestion de clientes de un proveedor
de servicios de internet (ISP). Permite administrar clientes, paquetes de
internet, pagos, instalaciones y folios de reparacion.

El sistema esta desarrollado con:
- Backend: Node.js + Express + SQLite
- Frontend: React + Vite
- Autenticacion: JWT (JSON Web Tokens)
- Base de datos: SQLite

CARACTERISTICAS DESTACADAS:
- Inicio automatico inteligente (detiene servidores anteriores)
- Navegador automatico (abre cuando la aplicacion esta lista)
- Instalacion automatica de dependencias
- Gestion de servidores automatica


========================================
2. CARACTERISTICAS PRINCIPALES
========================================

2.1 GESTION DE CLIENTES
-----------------------
- Agregar, editar, ver y eliminar clientes
- Campos disponibles:
  * Numero de cliente (unico, opcional)
  * Nombre (requerido)
  * Domicilio (requerido)
  * Telefono (opcional)
  * Email (opcional)
  * Tipo de red: Red Satelital o Red ONT (opcional)
  * Paquete de internet contratado
  * Anotaciones
- Busqueda de clientes por nombre, domicilio o numero de cliente
- Vista detallada del cliente con historial completo
- Exportacion a PDF con toda la informacion del cliente

2.2 GESTION DE PAQUETES
-----------------------
- Crear, editar y eliminar paquetes de internet
- Campos: nombre, velocidad, precio, descripcion
- Asignacion de paquetes a clientes

2.3 GESTION DE PAGOS
--------------------
- Registrar pagos personalizados por cliente
- Campos: cliente, monto, fecha de pago, numero de recibo, notas
- Historial completo de pagos por cliente
- Vista de todos los pagos con informacion del cliente
- Visualizacion de ingresos por mes
- Filtrado por fecha y cliente
- Exportacion a PDF de pagos mensuales

2.4 PROGRAMACION DE INSTALACIONES (ACTUALIZADO)
------------------------------------------------
- Agendar fechas de instalacion
- Tipos de instalacion:
  * Instalacion Nueva
  * Reinstalacion
  * Actualizacion
  * Migracion
  * Mantenimiento
- Estados: Pendiente, En Proceso, Completado, Cancelado
- Notas adicionales por instalacion
- NUEVO: Costo de instalacion (campo opcional)
- NUEVO: Estado de pago (pagado/no pagado)
- NUEVO: Solo las instalaciones pagadas se suman a los ingresos totales
- NUEVO: Visualizacion de costo de instalacion en la lista
- NUEVO: Indicador visual del estado de pago

2.5 GESTION DE INGRESOS (NUEVO)
--------------------------------
- Vista consolidada de todos los ingresos de la empresa
- Incluye:
  * Pagos regulares de clientes
  * Pagos por instalacion (solo los pagados)
- Resumen de ingresos:
  * Ingresos totales
  * Ingresos netos (descontando meses gratuitos)
  * Cantidad de instalaciones pagadas
  * Total de ingresos por instalaciones
- Filtrado por fecha
- Exportacion a PDF

2.6 SISTEMA DE FOLIOS
---------------------
- Crear folios para visitas de reparacion
- Generacion automatica de numeros de folio unicos
- Campos: cliente, fecha de visita, descripcion del problema,
  estado, notas del tecnico
- Seguimiento de reparaciones

2.7 SISTEMA DE USUARIOS Y ROLES
--------------------------------
- Autenticacion segura con login y contraseña
- Tres tipos de roles:
  * Administrador: acceso completo (crear, leer, actualizar, eliminar)
  * Editor: puede crear, leer y actualizar (no puede eliminar)
  * Visualizador: solo puede crear y leer (no puede actualizar ni eliminar)
- Gestion de usuarios (solo administradores)
- Cambio de contraseña y nombre de usuario

2.8 EXPORTACION A PDF
---------------------
- Descarga de informacion completa del cliente en PDF
- Incluye: datos personales, historial de pagos, instalaciones y folios
- Exportacion de pagos mensuales a PDF
- Incluye resumen de ingresos por instalaciones


========================================
3. FUNCIONALIDADES AUTOMATICAS (NUEVO)
========================================

3.1 INICIO AUTOMATICO INTELIGENTE
----------------------------------
El sistema ahora detiene automaticamente cualquier servidor anterior
antes de iniciar nuevos servidores, evitando conflictos de puertos.

Caracteristicas:
- Deteccion automatica de procesos en puertos 3000 y 5000
- Detencion automatica de procesos anteriores
- Espera de 2 segundos para liberar puertos
- Inicio limpio sin intervencion manual
- Compatible con Windows, Linux y macOS

Como funciona:
1. Al ejecutar npm run dev o el script BAT, el sistema verifica si hay
   servidores corriendo en los puertos 3000 y 5000
2. Si encuentra procesos, los detiene automaticamente
3. Espera 2 segundos para que los puertos se liberen
4. Inicia los nuevos servidores
5. No es necesario detener servidores manualmente antes de iniciar

3.2 NAVEGADOR AUTOMATICO
------------------------
El sistema abre automaticamente el navegador cuando la aplicacion
esta lista para usar.

Caracteristicas:
- Espera a que ambos servidores (backend y frontend) esten listos
- Verifica que los puertos respondan correctamente
- Abre el navegador en http://localhost:3000
- Compatible con Windows, Linux y macOS
- Muestra mensajes informativos durante la espera

Como funciona:
1. El script open-browser.js se ejecuta en paralelo con los servidores
2. Verifica cada 5 segundos si los servidores estan listos
3. Cuando ambos servidores responden, abre el navegador
4. Muestra mensajes de progreso en la consola

3.3 INSTALACION AUTOMATICA DE DEPENDENCIAS
-------------------------------------------
El sistema instala automaticamente las dependencias si faltan.

Caracteristicas:
- Verifica si node_modules existe y tiene contenido
- Verifica dependencias criticas (express, multer, react, etc.)
- Instala automaticamente si faltan dependencias
- Muestra mensajes informativos durante la instalacion
- Compatible con Windows, Linux y macOS

Como funciona:
1. Al ejecutar npm run dev, se ejecuta ensure-dependencies.js
2. Verifica dependencias en raiz, server y client
3. Instala automaticamente si faltan
4. Continua con el inicio de la aplicacion

3.4 GESTION DE SERVIDORES
--------------------------
Scripts para gestionar servidores de forma automatica.

Scripts disponibles:
- npm run stop:servers - Detiene servidores en puertos 3000 y 5000
- bat-scripts\DETENER_SERVIDORES.bat - Script BAT para Windows
- Scripts ejecutan automaticamente antes de iniciar la aplicacion

Modo silencioso:
- Los scripts se pueden ejecutar en modo silencioso (--silent)
- No muestra mensajes cuando se ejecuta automaticamente
- Muestra mensajes detallados cuando se ejecuta manualmente

5. REQUISITOS DEL SISTEMA
========================================

5.1 REQUISITOS MINIMOS
----------------------
- Sistema Operativo: Windows 10/11, Linux, macOS
- Node.js: Version 14 o superior
- npm: Version 6 o superior (incluido con Node.js)
- Navegador web moderno: Chrome, Firefox, Edge, Safari

5.2 ESPACIO EN DISCO
--------------------
- Aproximadamente 200 MB para dependencias
- Base de datos: crece segun los datos almacenados

5.3 PUERTOS NECESARIOS
----------------------
- Puerto 5000: Servidor backend (configurable)
- Puerto 3000: Cliente frontend (configurable)

NOTA: Los puertos se liberan automaticamente al iniciar la aplicacion.
El sistema detiene servidores anteriores antes de iniciar nuevos.


========================================
6. INSTALACION Y CONFIGURACION
========================================

6.1 INSTALACION DE NODE.JS
--------------------------
1. Descargar Node.js desde: https://nodejs.org/
2. Instalar la version LTS (recomendada)
3. Durante la instalacion, marcar "Add to PATH"
4. Reiniciar la terminal/PowerShell

6.2 INSTALACION DEL PROYECTO (METODO AUTOMATICO - RECOMENDADO)
---------------------------------------------------------------
METODO 1: Instalacion automatica (Windows)
1. Doble clic en: bat-scripts\INSTALAR_PROGRAMA.bat
2. El script instalara todas las dependencias automaticamente
3. Creara un acceso directo en la carpeta del proyecto
4. Listo para usar

METODO 2: Instalacion automatica (Linea de comandos)
1. Abrir terminal en la carpeta del proyecto
2. Ejecutar: npm run dev
3. Las dependencias se instalaran automaticamente si faltan
4. La aplicacion iniciara automaticamente
5. El navegador se abrira automaticamente cuando este lista

6.3 INSTALACION MANUAL (OPCIONAL)
----------------------------------
Si prefieres instalar manualmente:

1. Instalar dependencias del proyecto raiz:
   npm install

2. Instalar dependencias del servidor:
   cd server
   npm install
   cd ..

3. Instalar dependencias del cliente:
   cd client
   npm install
   cd ..

O usar el comando que instala todo:
   npm run install-all

6.4 CONFIGURACION
-----------------
La aplicacion funciona con configuracion por defecto. Si necesitas cambiar
puertos, edita:
- server/index.js: Puerto del servidor backend (default: 5000)
- client/vite.config.js: Puerto del cliente frontend (default: 3000)

6.5 CREAR ACCESO DIRECTO
------------------------
Para crear un acceso directo dentro de la carpeta del proyecto:

METODO 1: Comando NPM (Recomendado)
npm run create-shortcut

METODO 2: Script VBScript
cscript scripts/create-shortcut.vbs

Se creara un acceso directo llamado "Sistema ISP CDCom.lnk" en la carpeta
del proyecto. El acceso directo iniciara la aplicacion automaticamente.


========================================
7. ESTRUCTURA DE BASE DE DATOS
========================================

7.1 TABLA: users
-----------------
- id: INTEGER PRIMARY KEY
- username: TEXT UNIQUE NOT NULL
- password: TEXT NOT NULL (hash bcrypt)
- role: TEXT DEFAULT 'viewer' (admin, editor, viewer)
- created_at: DATETIME

7.2 TABLA: packages
-------------------
- id: INTEGER PRIMARY KEY
- name: TEXT NOT NULL
- speed: TEXT NOT NULL
- price: REAL NOT NULL
- description: TEXT
- created_at: DATETIME

7.3 TABLA: clients
------------------
- id: INTEGER PRIMARY KEY
- client_number: TEXT UNIQUE (opcional)
- name: TEXT NOT NULL
- address: TEXT NOT NULL
- phone: TEXT (opcional)
- email: TEXT (opcional)
- network_type: TEXT (opcional: "Red Satelital" o "Red ONT")
- package_id: INTEGER (FK a packages)
- notes: TEXT (opcional)
- created_at: DATETIME

7.4 TABLA: payments
--------------------
- id: INTEGER PRIMARY KEY
- client_id: INTEGER NOT NULL (FK a clients)
- amount: REAL NOT NULL
- payment_date: DATE NOT NULL
- receipt_number: TEXT (opcional)
- notes: TEXT (opcional)
- is_free_month: INTEGER DEFAULT 0 (NUEVO: mes gratuito)
- created_at: DATETIME

7.5 TABLA: installations (ACTUALIZADO)
---------------------------------------
- id: INTEGER PRIMARY KEY
- client_id: INTEGER (FK a clients, puede ser NULL para instalaciones sin cliente)
- custom_name: TEXT (NUEVO: nombre personalizado si no hay cliente)
- address: TEXT (NUEVO: direccion si no hay cliente)
- installation_date: DATE NOT NULL
- installation_type: TEXT NOT NULL
- status: TEXT DEFAULT 'pendiente'
- notes: TEXT (opcional)
- installation_fee: REAL DEFAULT 0 (NUEVO: costo de instalacion)
- is_paid: INTEGER DEFAULT 0 (NUEVO: estado de pago: 0=no pagado, 1=pagado)
- created_at: DATETIME

NOTA: Solo las instalaciones con is_paid=1 se suman a los ingresos totales.

7.6 TABLA: folios
-----------------
- id: INTEGER PRIMARY KEY
- client_id: INTEGER NOT NULL (FK a clients)
- folio_number: TEXT UNIQUE NOT NULL
- visit_date: DATE NOT NULL
- problem_description: TEXT (opcional)
- status: TEXT DEFAULT 'pendiente'
- technician_notes: TEXT (opcional)
- created_at: DATETIME

========================================
10. API ENDPOINTS
========================================

10.1 AUTENTICACION
------------------
POST /api/auth/login
  - Body: { username, password }
  - Response: { token, user }

POST /api/auth/change-password
  - Headers: Authorization: Bearer {token}
  - Body: { oldPassword, newPassword }
  - Response: { message }

PUT /api/auth/change-username
  - Headers: Authorization: Bearer {token}
  - Body: { newUsername }
  - Response: { message, username }

GET /api/auth/me
  - Headers: Authorization: Bearer {token}
  - Response: { id, username, role, created_at }

10.2 USUARIOS (Solo Administradores)
------------------------------------
GET /api/users
  - Headers: Authorization: Bearer {token}
  - Response: [{ id, username, role, created_at }]

POST /api/users
  - Headers: Authorization: Bearer {token}
  - Body: { username, password, role }
  - Response: { id, message, username, role }

PUT /api/users/:id
  - Headers: Authorization: Bearer {token}
  - Body: { username?, password?, role? }
  - Response: { message }

DELETE /api/users/:id
  - Headers: Authorization: Bearer {token}
  - Response: { message }

10.3 CLIENTES
-------------
GET /api/clients
  - Headers: Authorization: Bearer {token}
  - Response: [{ id, client_number, name, address, ... }]

GET /api/clients/:id
  - Headers: Authorization: Bearer {token}
  - Response: { id, client_number, name, ..., payments, installations, folios }

POST /api/clients
  - Headers: Authorization: Bearer {token}
  - Body: { client_number?, name, address, phone?, email?, network_type?, package_id?, notes? }
  - Response: { id, message }

PUT /api/clients/:id
  - Headers: Authorization: Bearer {token}
  - Body: { client_number?, name, address, phone?, email?, network_type?, package_id?, notes? }

13. SOLUCION DE PROBLEMAS
========================================

13.1 ERROR: "npm no se reconoce"
--------------------------------
SOLUCION:
1. Verificar que Node.js este instalado: node --version
2. Si no esta instalado, descargar desde https://nodejs.org/
3. Durante la instalacion, marcar "Add to PATH"
4. Reiniciar la terminal

13.2 ERROR: "Puerto 5000 en uso" (ACTUALIZADO)
-----------------------------------------------
SOLUCION AUTOMATICA:
- El sistema detiene automaticamente servidores anteriores
- Si el error persiste, ejecutar: npm run stop:servers
- O ejecutar: bat-scripts\DETENER_SERVIDORES.bat

SOLUCION MANUAL:
1. Cerrar otras aplicaciones que usen el puerto 5000
2. O cambiar el puerto en server/index.js:
   const PORT = process.env.PORT || 5001; // Cambiar a otro puerto

13.3 ERROR: "Puerto 3000 en uso" (ACTUALIZADO)
-----------------------------------------------
SOLUCION AUTOMATICA:
- El sistema detiene automaticamente servidores anteriores
- Si el error persiste, ejecutar: npm run stop:servers
- O ejecutar: bat-scripts\DETENER_SERVIDORES.bat

SOLUCION MANUAL:
1. Cerrar otras aplicaciones que usen el puerto 3000
2. O cambiar el puerto en client/vite.config.js:
   server: { port: 3001 } // Cambiar a otro puerto

13.4 ERROR: "EADDRINUSE: address already in use :::5000" (NUEVO)
-----------------------------------------------------------------
SOLUCION:
1. El sistema detiene automaticamente servidores anteriores
2. Si el error persiste:
   - Ejecutar: npm run stop:servers
   - O ejecutar: bat-scripts\DETENER_SERVIDORES.bat
   - Esperar 2 segundos
   - Ejecutar: npm run dev
3. Verificar que no haya otros procesos usando los puertos
4. Usar el script de diagnostico: bat-scripts\DIAGNOSTICO.bat

13.5 ERROR: "Cannot find module 'multer'" (ACTUALIZADO)
-------------------------------------------------------
SOLUCION AUTOMATICA:
- Ejecutar: npm run dev
- Las dependencias se instalaran automaticamente

SOLUCION MANUAL:
1. Ejecutar: npm run install-all
2. O ejecutar manualmente:
   cd server
   npm install
   cd ..

13.6 ERROR: "Token invalido o expirado"
----------------------------------------
SOLUCION:
1. Cerrar sesion y volver a iniciar sesion
2. El token expira despues de 24 horas

13.7 ERROR: "No tienes permisos"
---------------------------------
SOLUCION:
1. Verificar que tu usuario tenga el rol adecuado
2. Si eres admin, verificar en la seccion de Usuarios
3. Si no eres admin, contactar a un administrador

13.8 LA APLICACION NO CARGA (ACTUALIZADO)
------------------------------------------
SOLUCION:
1. Verificar que ambos servidores esten corriendo
2. Revisar las terminales para ver errores
3. Abrir la consola del navegador (F12) para ver errores
4. Ejecutar el script de diagnostico: bat-scripts\DIAGNOSTICO.bat
5. Verificar que los puertos 3000 y 5000 esten disponibles
6. Detener servidores anteriores: npm run stop:servers
7. Reiniciar la aplicacion: npm run dev

13.9 ERROR AL CREAR CLIENTE: "Numero de cliente ya en uso"
-----------------------------------------------------------
SOLUCION:
1. El numero de cliente debe ser unico
2. Usar un numero diferente o dejar el campo vacio

13.10 BASE DE DATOS CORRUPTA
-----------------------------
SOLUCION:
1. Hacer backup de server/database.sqlite
2. Eliminar server/database.sqlite
3. Reiniciar el servidor (se creara una nueva base de datos)
4. El usuario admin se creara automaticamente

13.11 EL NAVEGADOR NO SE ABRE AUTOMATICAMENTE (NUEVO)
------------------------------------------------------
SOLUCION:
1. Verificar que los servidores esten corriendo
2. Esperar unos segundos (el script espera hasta 5 minutos)
3. Abrir manualmente: http://localhost:3000
4. Verificar que los puertos 3000 y 5000 esten respondiendo
5. Revisar la consola para ver mensajes del script open-browser.js

13.12 PROBLEMAS AL DETENER SERVIDORES (NUEVO)
----------------------------------------------
SOLUCION:
1. Ejecutar: npm run stop:servers
2. O ejecutar: bat-scripts\DETENER_SERVIDORES.bat
3. Si no funciona, cerrar manualmente las ventanas de Node.js
4. Verificar que los puertos esten libres: netstat -ano | findstr ":5000"
5. Si hay procesos, detenerlos manualmente con Task Manager

13.13 DIAGNOSTICO DEL SISTEMA (NUEVO)
--------------------------------------
Para diagnosticar problemas del sistema:
1. Ejecutar: bat-scripts\DIAGNOSTICO.bat
2. El script verificara:
   - Node.js y npm instalados
   - Estructura del proyecto
   - Dependencias instaladas

15. SEGURIDAD
========================================

15.1 AUTENTICACION
------------------
- Usar contraseñas seguras (minimo 6 caracteres, recomendado 8+)
- Cambiar la contraseña del usuario admin por defecto
- No compartir credenciales

15.2 TOKENS JWT
---------------
- Los tokens expiran despues de 24 horas
- Los tokens se almacenan en localStorage del navegador
- Cerrar sesion cuando se termine de usar

15.3 ROLES Y PERMISOS
---------------------
- Asignar roles apropiados a cada usuario
- Usar el rol "viewer" para usuarios que solo necesitan ver
- Usar el rol "editor" para usuarios que necesitan editar
- Solo administradores deben tener rol "admin"

15.4 BASE DE DATOS
------------------
- La base de datos SQLite esta en el servidor
- No exponer la base de datos directamente
- Hacer respaldos regulares
- Proteger el acceso al servidor

15.5 PRODUCCION
---------------
- Cambiar JWT_SECRET en produccion
- Cambiar credenciales por defecto
- Usar HTTPS en produccion
- Configurar firewall apropiado
- Hacer respaldos automaticos
